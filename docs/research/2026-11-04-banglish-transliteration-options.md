# Banglish transliteration options

Research date: 4 November 2026. Sources below are maintainer repositories, package metadata, or model/dataset cards. This is source research only; no package was installed and no model was run.

## Current SafeHer fit

SafeHer's Python preprocessor transliterates Banglish before both direct chat and RAG retrieval. The existing character map generates unnatural output (`amake` becomes character-wise Bengali), so a purpose-built parser/model can improve the input text without changing the chat APIs.

## Candidates

| Candidate | Evidence and license | Runtime fit | Caveat |
|---|---|---|---|
| [`avro.py`](https://github.com/hitblast/avro.py) / [PyPI](https://pypi.org/project/avro.py/) | Bengali Avro phonetic parser. Maintainer example converts `ami banglay gan gai.` to `আমি বাংলায় গান গাই।`; supports whole strings and has a dictionary-based parser. Latest PyPI release shown is `2025.11.3` (2 Nov 2025); package metadata says Python `>=3.10`, MIT OR Apache-2.0, and no runtime dependencies. | **Best first integration candidate.** Local, deterministic, no model download or external API; fits SafeHer's Python 3.12 and Lite Mode. | The project's remapped exception dictionary is explicitly a work in progress. It converts some English proper names (example: `Microsoft` → `মাইক্রোসফট`), so SafeHer should preserve URLs, email, numbers, and selected English/code-mixed tokens before calling it. It uses Avro phonetic conventions, not a contextual neural model. |
| AI4Bharat [IndicXlit](https://github.com/AI4Bharat/IndicXlit) / [Python package](https://pypi.org/project/ai4bharat-transliteration/) | Multilingual Roman↔native transliteration including Bengali; repository describes an ~11M parameter model and reports evaluation on Dakshina and Aksharantar. It exposes `XlitEngine` with top-k word suggestions and sentence API; repository and PyPI metadata say MIT. | Can run locally after fetching the model. Also has an official hosted UI/API. | Python package latest release shown is `1.1.3` (14 Sep 2022); README says CLI expects words and requires sentence splitting. The model zip is fetched separately, adding startup/deployment and network concerns. Upstream issues include Fairseq install/import failures. An older archived AI4Bharat repo describes model artifacts under CC BY-SA 4.0 while the current IndicXlit repo says MIT; check the specific model release metadata before redistribution. Hosted input would send user text off-device. |
| [`nahidstaq/bangla-transliteration`](https://huggingface.co/nahidstaq/bangla-transliteration) | Direct Romanized Bangla→Bangla character-level model, MIT. Its card reports 6M parameters, 24 MB, CPU inference, and 9.18% character error rate on 2,429 held-out pairs. | Closest model-card task match; PyTorch inference is local once weights are available. | HF currently gates file access behind agreeing to share account information; it has no Inference Provider. The reported exact-match result is 17.9%, it's greedy/no beam search, and the author says the data is social-media/forum text and formal Bangla may differ. Only 41,785 gold training pairs are listed. This is not yet a frictionless SafeHer dependency. |
| [`sk-community/romanized-bengali-transliterator-60M`](https://huggingface.co/sk-community/romanized-bengali-transliterator-60M) | Bengali-focused Marian Seq2Seq model, MIT, with 60.6M parameters and a 245 MB repository. Its card reports BLEU 77.82, CER 0.16, and WER 0.25. | Local inference through Transformers/PyTorch; the repository files are public and there is no hosted inference provider. | Its card says the 975k Bengali pairs were generated by rule-based transliteration from Wikipedia, so noisy Bangladeshi chat spellings may be underrepresented. The example model ID uses underscores and does not match the actual repository slug; verify the published load path before integrating. The weights and ML runtime do not fit SafeHer's default 512 MB Lite Mode comfortably. |
| [`fms-byte/banglish_to_bangla`](https://huggingface.co/fms-byte/banglish_to_bangla) | Model card claims Banglish→Bengali, Apache 2.0, fine-tuned from mBART. | Would require Transformers and a large seq2seq base model. | Card has a placeholder `your-username` repository and placeholder demo, says mixed-language input is out of scope, and documents a `translation` pipeline path that's no longer supported in Transformers 5. Not recommended without independent artifact/provenance verification. |

## Data for a future local evaluation

- [BanglaTLit on Hugging Face](https://huggingface.co/datasets/aplycaebous/BanglaTLit) is MIT-licensed and contains 42,705 aligned Romanized-Bangla/Bangla examples plus a larger pretraining split. Examples are social-forum language; review data-use and quality before using it to claim app accuracy.
- [Bengali-to-Banglish-Dataset](https://huggingface.co/datasets/ShayonSarker/Bengali-to-Banglish-Dataset) advertises 206,926 word entries and MIT, with multiple conversational spellings. Its dataset card says variants are algorithmically generated; the current HF viewer also reports a column/schema error. Treat it as a candidate lexicon, not gold evaluation data, until schema and sample quality are checked.

## Recommendation

Try `avro.py` first behind SafeHer's existing `transliterate_banglish`/`transliterate_mixed` interface. The GitHub project is actively maintained, and its small dependency-free Python package is the lowest-risk fit for the default Python 3.12 backend. Its whole-string phonetic parser directly addresses the current character-wise output problem. Keep a wrapper that preserves URLs, email, numbers, and selected English/code tokens; make the library replaceable. Compare it locally against a small human-reviewed set of Bangladesh emergency/chat phrases before deciding whether to adopt it. Do not send emergency chat text to a hosted transliteration API.

The hosted AI4Bharat demo is available for public sample phrases, but it is not a privacy-appropriate production dependency for SOS text. The Hugging Face model is a possible later local benchmark if its gated artifact access and deployment footprint are acceptable.
